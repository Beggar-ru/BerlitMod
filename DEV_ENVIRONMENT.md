# Рабочее окружение Berlit

Документ описывает окружение для работы над модом и то, как им пользоваться.
Всё, что нужно для сборки, восстанавливается из репозитория тремя командами —
см. «Восстановление с нуля» ниже.

## Что установлено

| Компонент | Где | Зачем |
|---|---|---|
| JDK 25 (Temurin 25.0.5) | `.tools\jdk-25` | Gradle-демон (`.java-version` = 25) |
| JDK 21 (Temurin 21.0.13) | `.tools\jdk-21` | тулчейн для `applyJST` (RFG-трансформер) |
| JDK 17 (Temurin 17.0.20.1) | `.tools\jdk-17` | тулчейн для `compileInjectedInterfacesJava` |
| JDK 8 (Temurin 1.8.0_512) | `.tools\jdk-8` | тулчейн целевой версии мода |
| Gradle 9.7.1 | `.gradle-home\wrapper\dists` | скачивается wrapper'ом, версия из `gradle/wrapper/gradle-wrapper.properties` |
| Gradle-кэш и daemon | `.gradle-home` | `GRADLE_USER_HOME`, чтобы не писать в `%USERPROFILE%` |
| Локальное Maven-зеркало | `.tools\local-maven` | jar'ы, которые не отдаёт GTNH Nexus (~78 МБ) |
| Python + Pillow 12.3 | путь записан в `.tools\python.txt` | генераторы `tools\gen_*.py` и превью-инструменты |

`.tools\` и `.gradle-home\` перечислены в `.gitignore` — в репозиторий они не попадают.

## Восстановление с нуля

```powershell
python tools\env\fetch_jdks.py      # JDK 25/21/17/8 через API Adoptium
python tools\env\mirror.py          # jar'ы с GitHub Releases -> .tools\local-maven
.\tools\dev-env.ps1 build           # собрать мод
```

Оба скрипта качают через Python (`urllib` и его собственный OpenSSL), потому что
системный TLS на этой машине сломан, а авто-скачивание тулчейнов через foojay на
этой сети отваливается по таймауту.

`dev-env.ps1` при первом запуске сам создаёт `.gradle-home\gradle.properties`
(абсолютные пути к JDK, обходы песочницы, таймауты сети) и копирует
`tools\env\local-mirror.gradle` в `.gradle-home\init.d`. Оба файла машинно-зависимые
и генерируются, править их руками не нужно: удалите `gradle.properties`, и он будет
создан заново.

Проверить, что зеркало на месте: `python tools\env\mirror.py --list`.


## Быстрый старт

Два равноправных способа. Первый — запустить задачу напрямую, второй — загрузить
окружение в сессию и пользоваться короткими командами:

```powershell
.\tools\dev-env.ps1 build          # собрать мод -> build\libs\berlit-<версия>.jar
.\tools\dev-env.ps1 runClient      # запустить клиент
.\tools\dev-env.ps1 preview check  # линтер GUI/текстур
```

```powershell
. .\tools\dev-env.ps1              # ОБРАТИТЕ ВНИМАНИЕ: точка и пробел
gw build
gw runClient
pv check
pv sheet
```

Важно: `. .\tools\dev-env.ps1` (через точку) выполняет скрипт **в текущей сессии** и
оставляет функции `gw`/`pv` доступными. Запись `.\tools\dev-env.ps1 gw runClient`
запускает скрипт как отдельную программу — функции исчезнут вместе с ним, поэтому
такой вызов отвечает «Имя "gw" не распознано». В режиме запуска аргументы передаются
прямо в Gradle, поэтому правильная форма — `.\tools\dev-env.ps1 runClient`.

Чтобы `gw`/`pv` были всегда, добавьте строку в профиль PowerShell (`notepad $PROFILE`):

```powershell
. C:\Users\SERVER\Desktop\BerlitMod\tools\dev-env.ps1
```

Сборка проверена на этом чекауте: `BUILD SUCCESSFUL`, на выходе
`build\libs\berlit-0.21.1-main+2ab71d4ade-dirty.jar` (148 классов, 53 текстуры блоков,
14 предметов, 7 GUI-текстур, `en_US`/`ru_RU`, `mixins.berlit.json` с refmap).

## Особенность этой машины: сломан системный TLS

`Schannel` (TLS в Windows) не работает: `AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`.
Из-за этого падают `curl.exe`, `Invoke-WebRequest`, git с бэкендом по умолчанию.

Что сделано:

- в этом репозитории выставлен `git config http.sslBackend openssl` — `git pull`/`push` работают;
- скачивание JDK идёт через Python (у него свой OpenSSL);
- Gradle качает зависимости своим HTTP-стеком на Java (JSSE), поэтому сборка не затронута.

Если понадобится другой инструмент с HTTPS — запускайте его через Python или Java,
либо добавьте `-c http.sslBackend=openssl` для git-команд в других репозиториях.

## Nexus отдаёт pom, но не отдаёт jar

`nexus.gtnewhorizons.com` отвечает на `.pom`, `.module` и `.sha1` нормально, а на `.jar`
присылает заголовки с `Content-Length` — и обрывает соединение, так и не отдав тело.
Проверено с Python/OpenSSL, Node и Java, по HTTPS и по HTTP. Обрыв привязан не к пути,
а к объёму: **Range-запрос до 16 КБ проходит (206), всё крупнее — таймаут**.
GitHub Releases, Maven Central и services.gradle.org при этом работают нормально.

### Обход: локальное зеркало

`tools\env\mirror.py` собирает Maven-репозиторий `.tools\local-maven`:

- **jar — с GitHub Releases**: GTNH публикует туда каждый артефакт с нужным
  классификатором (`-dev`, `-api`, `-dev-preshadow`);
- **pom — с Nexus**: текст отдаётся, и Gradle видит настоящие зависимости;
- **единственное исключение** — `jabel-javac-plugin:1.0.2-GTNH`: у тега на GitHub нет
  ассетов, jitpack отдаёт 404/401, поэтому его jar (27 КБ) собирается по чанкам
  16 КБ через Range-запросы (см. `fetch_chunked` в том же скрипте).

`.gradle-home\init.d\local-mirror.gradle` ставит зеркало **перед** Nexus в
`pluginManagement`, `dependencyResolutionManagement` и `repositories` проектов,
поэтому Gradle находит jar локально и не ждёт таймаут.

Соответствие «координаты → URL» — словарь `MANIFEST` в `tools\env\mirror.py`.
Если появится новая недоступная зависимость, Gradle назовёт её в тексте ошибки:
допишите пару в `MANIFEST` и запустите `python tools\env\mirror.py`.

## Песочница, временные файлы и компиляция

Три отдельные проблемы этой среды, все решены настройками в `.gradle-home\gradle.properties`:

1. **Слежение за файлами и нативная интеграция.** Песочница запрещает Gradle обращаться
   к нативным потокам, и сборка зависает с `Couldn't open current thread, error = 5`.
   Отключены `org.gradle.vfs.watch` и `org.gradle.native`, а `gw` добавляет `--no-watch-fs`.
2. **Временная папка.** Плагин spotless/blowdryer не может создать кэш в системном `%TEMP%`,
   поэтому `java.io.tmpdir` (и `TMP`/`TEMP` в `dev-env.ps1`) указывают на `.gradle-home\tmp`.
3. **Компиляция.** Jabel подключается к процессу javac через именованный канал Windows,
   а песочница такие каналы запрещает (`Win32Exception: Отказано в доступе` в
   `ByteBuddyAgent...NamedPipe`). Поэтому сборку нужно запускать вне песочницы DSH —
   с полным доступом к файлам или из обычного терминала.
4. **Configuration cache.** Gradle 9 включает её по умолчанию, а `Download`-задача RFG
   в неё не сериализуется (`sourceObjects` / `HttpHostConnectException`). Отключена:
   `org.gradle.configuration-cache=false`.

### Политика выполнения PowerShell

`Get-ExecutionPolicy` = `Restricted` (во всех областях `Undefined`), поэтому
`.\tools\dev-env.ps1` без подготовки не запустится: «выполнение сценариев отключено
в этой системе». Разово:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

или на одну сессию: `Set-ExecutionPolicy -Scope Process Bypass -Force`.

Вторая ловушка той же природы: Windows PowerShell 5.1 добавляет BOM при
`Set-Content -Encoding UTF8`, а Gradle и Groovy его не переваривают — BOM в
`.gradle.properties` ломает первый ключ, BOM в init-скрипте даёт
`Unexpected character: '﻿'` при компиляции Groovy. Поэтому `dev-env.ps1` пишет
сгенерированные файлы через `[System.IO.File]::WriteAllText` с `UTF8Encoding($false)`.

## Инструменты для интерфейса и текстур

`tools\preview.py` — единая точка входа (нужен только Pillow, как и `gen_*.py`):

```powershell
pv sheet                  # контактный лист всех 16x16 текстур + макеты всех GUI
pv screens                # список экранов: имя, стиль, размер, число слотов
pv gui spawner_t2         # один макет с наложением сетки слотов
pv gui --grid matter_generator   # макет с линейкой координат и таблицей элементов
pv check                  # линтер, exit code 1 при ошибках
```

Что делает `pv check`:

1. **Геометрия GUI** — размер, режим RGBA, отсутствие прозрачных дыр в области 176x166.
2. **Совпадение текстуры и кода** — для каждого слота, который добавляет `Container`,
   проверяется, что в текстуре по этим координатам действительно нарисован слот
   (внутренняя заливка 16x16 однородна). Сдвиг на 1 пиксель уже ловится.
3. **Наложения** — слоты не пересекаются между собой и не наезжают на строки текста,
   которые рисует `drawGuiContainerForegroundLayer`.
4. **Длина строк по языкам** — ширина значения из `en_US`/`ru_RU` (с подставленным
   примером числа) сравнивается с отведённой под строку шириной.
5. **Переводы** — ключи, которые код реально запрашивает через `translateToLocal`,
   `getTitleKey`, есть в обоих языках; ключи en/ru рассинхронизированы — предупреждение.
6. **Ссылки на текстуры** — `berlit:textures/...` из Java существует на диске.
7. **Блоки и предметы** — 16x16, не полностью прозрачные, у предметов есть фон-прозрачность.
8. **NEI-страницы** — каждая страница (`nei_machines.png`, `nei_matter.png`, ...) имеет
   размер 176x166 без прозрачных дыр, у каждого предмета есть 18x18 ячейка слота,
   предметы не пересекаются между собой и со строками текста.

Макеты пишутся в `docs\preview\` (тоже исключено из git): слоты подписаны
(`i` — вход, `o` — выход, `u` — улучшения, `e` — сущности, `p` — инвентарь игрока),
голубые рамки — области строк текста.

### Оформление: тёмная тема slate + cyan

Интерфейс собран из **двух отдельных панелей**: панель механизма шире (200x140), инвентарь
игрока — отдельная плита 176x98 по центру под ней, между ними 8 px прозрачного зазора.
Общая высота экрана (`ySize`) — 246, обе панели рисуются из одной текстуры 256x256 по
разным смещениям, поэтому зазор остаётся прозрачным и сквозь него видно мир.

Внутри панели механизма: заголовок с бирюзовой подчёркивающей линией, слоты входа/выхода,
стрелка направления, полоса прогресса с насечками (заливку рисует `BerlitGui` в рантайме),
утопленный «колодец» под слоты улучшений и иконка `i` в правом нижнем углу — по наведению
она показывает тултип с энергией, потреблением и расходом на операцию.

Цепочка файлов — от раскладки к картинке:

| Файл | Роль |
|---|---|
| `tools\gui_layout.py` | координаты слотов (зеркало `Container*`), размеры панелей |
| `tools\gui_theme.py` | палитра и примитивы: рамка, тень, рамка прогресса, плитка слота |
| `tools\gen_gui_theme.py` | рисует обе панели и собирает текстуру 256x256 |
| `src\...\gui\BerlitGui.java` | размеры панелей, отрисовка панелей и заливки прогресса |
| `src\...\gui\GuiTheme.java` | цвета текста в игре |

```powershell
python tools\gen_gui_theme.py     # перерисовать текстуры
pv check                          # проверить, что слоты легли по координатам кода
pv gui --clean                    # макеты без оверлея, для оценки вида
```

Ключевой момент: `pv check` сравнивает каждую область слота 18x18 с эталонной плиткой
`gui_theme.TILE` пиксель в пиксель. Если поменять координаты в `Container` и забыть
перегенерировать текстуру, линтер скажет, на сколько процентов плитка не совпала.

Цвета текста вынесены в `GuiTheme.java` (`TEXT`, `TITLE`, `ACCENT`) — раньше в трёх
классах был жёстко зашит тёмно-серый `4210752`, который на тёмной панели не читается.

### NEI-страницы

Рецепты NEI рисуются на собственных страницах 176x166 в той же теме slate + cyan:
градиент панели, бирюзовая рамка с уголками, полоса заголовка, шевроны «вход → выход»
и ячейка слота под каждым предметом.

| Файл | Роль |
|---|---|
| `tools\gui_layout.py` → `NEI_PAGES` | координаты предметов и текста для каждой страницы |
| `tools\gen_nei_pages.py` | рисует `textures\gui\nei_<page>.png` из этой раскладки |
| `src\...\compat\nei\*NEI.java` | `getGuiTexture()` и `drawExtras()` — текст цветами `GuiTheme` |

```powershell
python tools\gen_nei_pages.py   # перерисовать страницы
pv check                        # проверить ячейки, дыры и наложения
```

Страница печётся из тех же координат, что и `PositionedStack` в хендлере: сдвинули
предмет — поправьте `NEI_PAGES` и перегенерируйте PNG, иначе `pv check` скажет, что под
предметом нет ячейки слота.

### Раскладки экранов

Два стиля: `machine` — панель механизма плюс отдельный инвентарь ниже; `panel` — один
экран целиком, как у AE2/Avaritia. Все восемь описаны в `tools\gui_layout.py`.

У каждого экрана теперь **свой блок инвентаря**: контент-панель сверху, зазор 8 px,
панель инвентаря 176x98 по центру снизу.

| Экран | Контент | Инвентарь (x, y) | Слоты контента |
|---|---|---|---|
| `molecular_transformer` (5 машин) | 200x140 | 12, 148 | 6 вход (38,22) / 6 выход (110,22) / 4 улучшения (64,92) |
| `spawner` | 200x140 | 12, 148 | 1 сущность (38,22) / 7 улучшений (64,92 и 64,110) |
| `spawner_t2` | 200x140 | 12, 148 | 10 сущностей (20,22) 5x2 / 7 улучшений |
| `avaritia_assembler` | 176x90 | 0, 98 | 3x3 сетка (44,20) |
| `pattern_encoder` | 220x196 | 22, 204 | сетка 9x9 (8,24), выход (190,96) по центру сетки |
| `singularity_encoder` | 176x76 | 0, 84 | вход (44,20), выход (116,20) |
| `neutron_compressor` | 176x90 | 0, 98 | вход (44,20), шаблон (80,20), выход (116,20) |
| `super_chest` | 502x190 | 163, 198 | 27x9 (8,18) |

Внутри панели инвентаря: подпись на +6, ряды на +18/+36/+54, хотбар на +74.
Текстуры: 256x256, у энкодера шаблонов 256x512, у супер-сундука 512x512 — размер берётся

Кнопки `C`, `64`, `E` рисует `ThemedButton` (тёмная плашка, бирюзовая рамка, подсветка

### Кит и экраны без текстур

Цвета собраны в `tools/palette.json` — единственный источник: его читают `gui_theme.py` и
`gen_kit.py`, а `tools/gen_theme_java.py` генерирует из него `GuiTheme.java`. Превью-лист палитры:
`python tools/palette_sheet.py`.

Виджетные экраны (сборщик Avaritia, нейтронный компрессор и все машинные экраны —
трансформер, дробитель, компрессор, металлоформовочный, прокатный, электропечь) устроены как в Luminous: экран вообще не имеет своей
PNG. Всё рисуется в рантайме из одного кита `textures/gui/kit.png` (64x64) в стиле машинок —
сланец, бирюзовая рамка с уголками, фаска у слотов; градиент панели `BerlitGui` накладывает
отдельным проходом, потому что 9-слайс растягивает один и тот же кусок:

| Область | Что | Отступ 9-слайса |
|---|---|---|
| (0,0) 24x24 | панель — только рамка, середина прозрачная | 8 |
| (24,0) 16x16 | кнопка | 4 |
| (0,24) 18x18 | ячейка слота | рисуется 1:1 |
| (24,24) 24x24 | тултип | 8 |

Градиент панели 9-слайс не умеет (он растягивает один кусок), поэтому `GuiAvaritiaAssembler`
сначала кладёт `drawGradientRect` с цветами машинных панелей (`GuiTheme.PANEL_TOP/BOTTOM`),
поверх — рамку из кита и длинные угловые скобки 14 px. `NineSlice.draw(x, y, w, h)` растягивает тайл под любой размер, `NineSliceButton` рисует
кнопку и иконку, `drawSprite` кладёт ячейку на слот. Геометрия каждого виджетного экрана живёт
в своём `*Layout` (`MachineLayout`, `AssemblerLayout`, `CompressorLayout`) и используется и
контейнером, и GUI. Геометрия экрана вынесена в
`AssemblerLayout` и используется **и** контейнером (позиции слотов), **и** GUI (что рисовать) —
поэтому картинка и хитбоксы не могут разъехаться.

Кнопки `C`/`64` заменены иконками: `one` — один крафт (`craftOnce()`), `stack` — 64 подряд.
Для таких экранов в раскладке стоит `style: "widget"`: генератор их пропускает, `pv check`
не сверяет слоты с текстурой (её нет), но проверяет наложения текста и кнопок, а `pv gui`
рисует макет прямо из кита.

При изменении `Container*` или `TileEntity*Spawner` правьте числа в `tools\gui_layout.py`
и в тех же местах в Java — линтер сверяет текстуру с раскладкой, а не с кодом.

## Найденные проблемы

- **`tools\gen_gui.py` и `tools\gen_transformer_gui.py` устарели.** Они рисуют
  `textures\gui\molecular_transformer.png` в старой светлой палитре и по старой геометрии
  (176x166, панель текста `[24,57]-[170,80]`, без 4 слотов улучшений). После появления
  `gen_gui_theme.py` они лишние: случайный запуск откатит интерфейс. Предлагаю удалить.
- **GUI 1.7.10 — 256x256 RGBA.** Все четыре GUI-текстуры этому соответствуют, линтер следит.
- **Счётчик улучшений у спавнера убран**: слоты теперь видны отдельным блоком, а строка
  «Улучшения: N» не помещалась на панели. Ключ `berlit.gui.spawner.upgrades` остался в lang.
- **Металлоформовочный разнесён на два блока.** Кнопки режима, пакета `PacketCycleMode` и
  переключения по Shift-клику нет; вместо одной машины с необъявленным режимом теперь
  `METAL_EXTRUDER` (выдавливание, `Recipes.metalformerExtruding`) и `METAL_ROLLER`
  (прокатка, `Recipes.metalformerRolling`). Режим задаётся типом машины
  (`MachineType.getDefaultMode()`), поэтому `mode` остаётся только ключом таблицы рецептов,
  а NEI показывает рецепты IC2 отдельной страницей для каждого блока.
